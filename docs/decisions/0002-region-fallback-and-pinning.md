# ADR-0002 · Цепочка источников по региону и SSL-pinning без бэкенда

Дата: 2026-09-08 · Статус: принято

## Контекст

Запросы идут с телефона. Binance отвечает `451` из США и ряда стран, регион
ревьюера Apple заранее неизвестен. Без запасного источника ревью увидит
пустой экран. Одновременно нужен pinning для `api.binance.com` и
`api.anthropic.com`, хотя ключи этих хостов мы не контролируем.

## Решение: источники

- Один интерфейс `MarketDataSource`, три реализации: Binance Global,
  Binance.US, CoinGecko. Feature-слой не знает, откуда пришла цена.
- Цепочка кандидатов при старте: `api.binance.com` → `data-api.binance.vision`
  (документированный хост только для рыночных данных, тот же `sourceId`) →
  `api.binance.us` → CoinGecko как REST-only fallback без проверки.
- Проба кандидата: REST `ping`, затем WebSocket-хендшейк с подпиской на
  один `btcusdt@miniTicker` и таймаутом 3 с. `200` при молчащем сокете не
  считается успехом: так выглядит half-open соединение.
- `451` это подтверждённый геоблок, следующий кандидат сразу. Таймаут, 5xx,
  сетевая ошибка это недоступность: один повтор через 5 с, потом следующий.
  Разница видна пользователю: плашка «недоступно в регионе» против
  «биржа не отвечает».
- Результат кэшируется на 24 ч, перепроверка по смене сети, по кнопке в
  настройках и при ручном выборе источника.
- CoinGecko: один demo-ключ на все установки, опрос раз в 60 с только в
  foreground, `429` показывается как «резервный источник исчерпал лимит».
  Timestamp OHLC у них это время закрытия свечи, адаптер вычитает
  гранулярность, чтобы кэш и чарт работали в одной системе `openTime`.
- Числа CoinGecko приходят как JSON-числа. Точность уже потеряна на их
  стороне; мы конвертируем через кратчайшую строку числа, а не через
  арифметику на `double`.

### Проверка хостов 2026-09-08

Из региона разработчика все три хоста Binance отвечают `200` на `ping`
(`tool/probe_sources.dart`). Проверка из US-региона требует VPN и входит в
критерии готовности; до неё цепочка остаётся полной, потому что укорачивать
её без данных нельзя.

## Решение: pinning

- SPKI-pinning в `IOHttpClientAdapter.validateCertificate`: обычная проверка
  цепочки и hostname остаётся, поверх неё сравнивается SHA-256 от
  SubjectPublicKeyInfo листового сертификата. `badCertificateCallback` не
  подходит: он вызывается только для сертификатов, уже не прошедших
  системную валидацию.
- SPKI извлекается собственным минимальным DER-парсером (60 строк) вместо
  зависимости на ASN.1-библиотеку; тест сверяет результат с `openssl`
  для RSA- и EC-ключей.
- Пины сняты 2026-09-08 и лежат в `pins.dart` с датой и сроками
  сертификатов.

### Известный компромисс

Dart отдаёт в `validateCertificate` только листовой сертификат, поэтому
пин промежуточного CA как запасной не работает. При ротации ключа на
стороне Binance или Anthropic приложение ломается до обновления. Это цена
pinning без своего бэкенда: нет сервера, который мог бы раздать новые пины.
Смягчение: пины хостов CoinGecko не заданы, fallback на цены продолжает
работать; после каждой ротации предыдущий пин остаётся рядом с новым.

### Момент проверки пина и ключ пользователя

Dio вызывает `validateCertificate` уже на ответе, то есть запрос к этому
моменту отправлен. Для рыночных данных это не страшно: мы ничего секретного
не отправляем, пин защищает от подмены ответа. Для Claude API это было бы
утечкой ключа пользователя перехватчику с доверенным в системе CA, поэтому
`SpkiPreflight` (`data_market/lib/src/http/spki_preflight.dart`) делает
отдельное TLS-рукопожатие до запроса и сверяет SPKI ещё до отправки байтов;
результат кэшируется на 10 минут. Плюс `followRedirects: false`, чтобы 3xx
не переслал заголовок `x-api-key` на другой хост.

Остаточный риск: перехватчик может вести себя по-разному на двух соединениях
(TOCTOU между рукопожатием проверки и запросом). Закрыть это без своего
HTTP-стека на `SecureSocket` нельзя, и для пет-проекта такая цена не
оправдана; риск записан здесь честно.

## Последствия

- Плюс: ревью Apple из любого региона видит живое приложение.
- Плюс: региональный и сетевой сбои различимы в UI и в Sentry.
- Минус: в режиме CoinGecko нет стакана, ленты, объёма и выбора интервала.
  Экран честно это показывает через `Capabilities`.
- Минус: срок жизни пинов ограничен сроком сертификатов (ближайший:
  `api.anthropic.com`, 2026-10-22). Дата перепроверки в календаре.
