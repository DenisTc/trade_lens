# ADR-0003 · Кто объявляет провайдеры интерфейсов

Дата: 2026-09-08 · Статус: принято

## Контекст

Feature-пакеты видят только `domain`, `core` и UI-пакеты (ADR-0001), но им
нужен активный `MarketDataSource`, список активов и состояние соединения.
Спека требует Riverpod как единственный DI-механизм, без GetIt, а сами
интерфейсы лежат в `domain`, который не зависит от Riverpod.

Варианты:

1. Провайдеры в `domain`. Тянет `riverpod_annotation` и codegen в пакет,
   который должен оставаться чистым Dart без зависимостей.
2. Каждая фича объявляет свои провайдеры и приложение переопределяет
   каждый. Четыре копии одного и того же, override-ы расползаются.
3. Отдельный пакет `features/shared` с провайдерами интерфейсов и
   общими виджетами. Фичи зависят от него, приложение переопределяет.

## Решение

Вариант 3. `features_shared` содержит:

- `marketDataSourceProvider` (`Future<MarketDataSource>`, keepAlive) —
  тело бросает `UnimplementedError`, приложение делает
  `overrideWith` на провайдер, который прогоняет `RegionResolver` и
  собирает Binance c `WsClient` либо CoinGecko.
- `assetsProvider`, `marketInstrumentsProvider`.
- `quoteProvider(instrument)` — family, autoDispose, `Stream<Quote>`.
  Экран пары и портфель, смотрящие одну пару, делят один провайдер;
  подписка на бирже живёт, пока жив последний потребитель.
- `quoteHistoryProvider(instrument)` — последние 60 цен для спарклайна.
- `connectionStatusProvider` — стрим `ConnectionStatus` из `domain`;
  приложение мапит на него состояние `WsClient`.
- `AsyncValueView`, `DataSourceBadge`.

Правила для `features_shared`: зависит только от `core` и `domain`
(плюс Riverpod). Архитектурный тест разрешает фичам зависеть от него и не
считает его «соседней фичей».

### Автоповтор Riverpod 3 выключен

Riverpod 3 по умолчанию повторяет упавший провайдер с экспоненциальной
задержкой, и на это время зависимые провайдеры видят `AsyncLoading`.
В TradeLens повторы уже живут в слое данных: `RetryInterceptor`, resolver
с повтором через 5 с, реконнект сокета. Второй цикл повторов поверх
первого прятал бы ошибку за лоадером на секунды, что противоречит правилу
«ни один экран не остаётся с вечным лоадером». Поэтому `ProviderScope`
приложения и контейнеры в тестах создаются с `retry: noRetry`, а
`marketDataSourceProvider` дополнительно помечен тем же.

## Последствия

- Плюс: один override на интерфейс, в одном месте (`apps/mobile/lib/di`).
- Плюс: тесты фич подменяют источник фейком через тот же override.
- Плюс: `domain` остаётся без Riverpod, `data_market` без Flutter.
- Минус: ещё один пакет. Цена за то, что направление зависимостей
  проверяется тестом, а не соглашением.
