# TradeLens: приложение с живыми котировками без своего бэкенда

Документ для будущего себя: что строим, зачем, какие границы, и как именно это собрано. Проект идёт итерациями: v1 это репозиторий для нанимающего менеджера и тимлида, v2 превращает его в полезный инструмент для бот-трейдеров, v3 добавляет локальный AI. Всё ниже, кроме раздела «Итерации», описывает v1.

## Что и зачем

### Зачем и для кого

Аудитория. Не пользователи, а три читателя: рекрутер, который открывает ссылку из LinkedIn на 30 секунд; тимлид, который смотрит README и структуру пакетов 5 минут; интервьюер, который просит открыть конкретный файл и объяснить решение.

Одна работа страницы. Закрыть девять пунктов из таблицы требований одним репозиторием: Riverpod, GitHub Actions, Fastlane, Patrol, SSL pinning, Remote Config и SDUI, атрибуция установок, интеграция LLM, CustomPainter. Каждая функция ниже привязана к строке в резюме, а не к «полезности» для пользователя.

Принцип отбора. Если функция не даёт строки в резюме и не нужна, чтобы приложение выглядело живым, она в не-скоупе. Приложение должно быть маленьким и законченным, а не большим и наполовину.

Правило «5 минут»: в проект попадает только то, о чём можно говорить пять минут с примером из своих рук. Это же правило действует для навыков в LinkedIn.

### Скоуп и не-скоуп

В скоупе · v1
Список пар с живой ценой и изменением за 24 ч

- Экран пары: свечной график, стакан top-10 (снапшот-стрим), лента сделок

- Портфель: ручной ввод позиций, оценка по живой цене, offline-кэш

- Экран «Инсайты»: server-driven из JSON в Remote Config

- AI-сводка по паре: стриминг из Claude API, tool use, structured output

- Deferred deep link с параметрами атрибуции, OneSignal-пуш

- 2 локали: en, ru

- Тесты unit / golden / Patrol, GitHub Actions, Fastlane в TestFlight

Не в скоупе · осознанно
- Торговля, аккаунты бирж, API-ключи пользователя

- Свой бэкенд, регистрация, синк между устройствами

- Публикация в сторы как цель. TestFlight-сборка через Fastlane обязательна, App Store релиз по желанию

- Фьючерсы, маржа, деривативы. Только спот

- Ценовые алерты: уходят в проект №6 (нативный плагин с Pigeon)

- Bybit, третья локаль, пагинация истории свечей: только при запасе времени

- Индикаторы на графике кроме объёма и одной MA

- gRPC / GraphQL ветка (отдельный опциональный проект №7)

- Монетизация, подписки, реклама

### Итерации: от showcase к продукту

Решение от 08.09.2026: не смешивать цели. Каждая итерация имеет свою аудиторию и свой критерий готовности, следующая не начинается, пока предыдущая не сдана.

| Итерация | Для кого | Что добавляется | Срок | Готово, когда |

| v1 · showcase | Рекрутер, тимлид, интервьюер | Всё, что описано в этом документе: живые котировки, чарт, портфель, region fallback, SDUI, облачная AI-сводка по ключу пользователя, deferred link, CI, TestFlight | 8 дней | Критерии готовности ниже выполнены, репозиторий закреплён, строки из LinkedIn-кита поставлены |

| v2 · бэктестер | Розничный бот-трейдер (Bitsgap, 3Commas, Pionex) | Пакет `backtest` на Dart: сетка и DCA по историческим свечам Binance, метрики (прибыль, сделки, просадка, комиссии), сделки на чарте, сравнение двух наборов параметров. AI-сводка переключается на объяснение результата бэктеста по посчитанным метрикам. Публикация в App Store и Google Play становится обязательной, появляются Terms of Use, поддержка, ответы на отзывы | +3–4 дня | Релиз в обоих сторах, первый внешний пользователь прошёл сценарий «пара → параметры → результат» без подсказок |

| v3 · локальный AI | Те же пользователи, без ключа Anthropic | Свой плагин `on_device_llm` на Swift и Kotlin через Pigeon: Apple Foundation Models на iOS 26 (iPhone 15 Pro+), ML Kit GenAI на Gemini Nano на Android (Pixel 8+ и часть флагманов). Абстракция `SummaryProvider` с автоматическим выбором: локально, если устройство умеет, иначе облако по ключу, иначе подсказка. Локальная ветка получает готовые метрики и отдаёт структурированный ответ, без tool use. Этот плагин заменяет пет-проект №6 «ценовые алерты» | +2–3 дня | Сводка работает офлайн на реальном iPhone 15 Pro+ и совместимом Android, значок «на устройстве» виден пользователю |

#### Принципы, зафиксированные заранее

- Движок бэктеста пишется на Dart с нуля, по открытым описаниям сеточных и DCA-стратегий. Код, формулы и фикстуры Rust-модуля Bitsgap не используются: это интеллектуальная собственность работодателя. До начала v2 Rust-код Bitsgap не открывать, источники алгоритма указать в README.

- Rust в v2 не берём. Один прогон это десятки тысяч свечей и десятки миллисекунд на Dart, обвязка flutter_rust_bridge съела бы два дня, а Rust FFI в резюме уже есть. Если в будущем появится перебор параметров, сначала изолят, потом замер, и только потом Rust.

- Ограничения бэктеста заявляются в приложении: без проскальзывания, частичных исполнений, точной цены внутри свечи, трейлинга, стоп-лосса и фьючерсов. Результат называется «оценкой по историческим свечам», не прогнозом.

- Интерфейсы для v2 и v3 закладываются в v1 без реализации: `SummaryProvider` с одной облачной реализацией и вход AI-сводки в виде посчитанных метрик, а не сырых свечей. Это стоит часа сейчас и экономит день потом.

- Сроки: v1 до 30.09.2026 вместе с остальным планом подготовки. v2 и v3 после, параллельно с откликами, без давления на дату.

### Условия источников: что можно, что обязательно, что проверить

Открытый доступ без ключа не равен праву показывать, хранить и передавать данные. Ниже записано то, что известно на 08.09.2026, и то, что нужно прочитать в актуальной редакции условий перед первой публичной сборкой. Дата проверки и ссылки на документы идут в README.

| Источник | Что используем | Что известно | Что проверить в условиях |

| Binance | Публичные market data: тикеры, свечи, стакан top-10, сделки. REST и WS без ключа, а также отдельные хосты только для рыночных данных `data-api.binance.vision` и `data-stream.binance.vision` | Binance API Terms ограничивают перепродажу и редистрибуцию данных как сервиса и использование бренда. Право показывать данные в стороннем приложении из текста условий по памяти не вытекает и не опровергается, его нужно найти в актуальной редакции | Точные формулировки про показ, локальное кэширование и передачу данных третьей стороне (в нашем случае свечи и стакан уходят в Claude API). Нужна ли атрибуция по тексту условий или это наша добрая воля |

| Bybit | Только при запасе времени, спот: тикеры, kline, orderbook, trades | Опубликованные Bybit API Terms содержат отдельные ограничения на repackaging, коммерческое использование и воспроизведение сервиса. Это не копия условий Binance | Читать целиком до подключения. Если ограничения шире, чем у Binance, Bybit не подключаем и пишем об этом в ADR |

| CoinGecko Demo API | Fallback: цены и изменение 24 ч батчем по 20 монетам через `simple/price`, OHLC через `coins/{id}/ohlc` | Нужен бесплатный demo-ключ. Лимиты на 09.2026 по странице тарифов: около 100 запросов в минуту и 10 000 в месяц на ключ. Условия требуют обновлять кэш не реже раза в 24 ч, защищать хранимые данные и удалять их после прекращения доступа. Атрибуция «Powered by CoinGecko» по их гайду | Актуальные лимиты и правила кэширования. Формулировку атрибуции и ссылку |

#### Потоки данных, которые надо честно описать в README и в privacy policy

- Локальный кэш: последние 500 свечей на пару и интервал и последний тикер в Drift. Срок жизни 24 ч, потом перезапрос. Кэш очищается при смене источника.

- Передача в Claude API: при нажатии «Сводка движения» свечи и стакан текущей пары уходят на api.anthropic.com вместе с ключом пользователя. Только по явному действию, с пояснением на экране перед первым вызовом.

- Тестовые фикстуры: записанные ответы API лежат в репозитории для тестов. Объём минимальный, персональных данных нет. Если условия источника запрещают хранение в открытом виде, фикстуры заменяются синтетическими.

- Наружу не уходит ничего другого: нет экспорта, шаринга снапшотов, своего сервера, аналитики рыночных данных.

- Пользовательское соглашение: условия CoinGecko требуют от приложения собственных Terms of Use и privacy policy для конечных пользователей. Обе страницы на GitHub Pages, ссылки из стора и из экрана «О приложении».

#### Ключ CoinGecko

Один demo-ключ на все установки. Квота 10 000 запросов в месяц делится между всеми пользователями, при опросе раз в 60 с в foreground это около 1 400 запросов в сутки с одного устройства. Для showcase это приемлемо, но поведение при исчерпании описано: приложение показывает «Резервный источник исчерпал лимит, повторите позже», не молчит. Ключ передаётся через `--dart-define-from-file`. Это прячет его от git, но не от извлечения из бинарника, и это честно записано в README как ограничение проекта без бэкенда.

#### Как это отражено в продукте

- Подпись источника внизу экрана пары и списка. Компонент `DataSourceBadge` берёт текст из активного `MarketDataSource`.

- Экран «О приложении»: источники со ссылками на условия, дата последней проверки, описание потоков данных, ссылка на privacy policy.

- Название, иконка и цвета не повторяют фирменный стиль ни одной биржи.

### Гео-ограничения: обязательный fallback

Запросы идут с телефона пользователя. Binance.com отвечает `451` из США и ряда стран, Bybit ограничивает по IP похожим образом. Регион ревьюера Apple заранее неизвестен, и рассчитывать на доступность Binance нельзя: без fallback ревью может увидеть пустой экран и отклонит с формулировкой «app does not function».

#### Выбор источника при старте

Binance Global: REST ping + короткий WS-хендшейк→ оба ок →Binance Global
| 451 →Binance US: REST + WS→ ок →Binance US
| 451 / ошибка →CoinGecko REST→режим «только цены»

- Проверяется реальная возможность, а не только REST: WS-хендшейк с подпиской на один miniTicker и таймаутом 3 с. REST 200 при мёртвом WS не считается успехом.

- Различаем два случая. `451` это подтверждённое региональное ограничение, и приложение переходит к следующему источнику. Таймаут или `5xx` это недоступность, приложение показывает «Источник недоступен, повтор» и повторяет через 5 с, потом переходит дальше. Иначе плохой Wi-Fi выглядел бы как геоблок.

- Хосты только для рыночных данных `data-api.binance.vision` и `data-stream.binance.vision` проверяются в день 2 как первый кандидат: если они доступны там, где закрыт api.binance.com, цепочка укорачивается. Обход ограничений не обещаем, это только выбор документированного хоста.

- Результат кэшируется на 24 ч, перепроверка при смене сети и по кнопке «Проверить источник» в настройках. Источник можно выбрать вручную, это нужно и для ревью, и для демонстрации.

- Режим «только цены»: список и портфель по опросу раз в 60 с в foreground, график по OHLC CoinGecko с их автоматической гранулярностью (около 30 мин, 4 ч, 4 дня в зависимости от диапазона) и без объёма. Селектор интервалов и стакан скрыты, подписи оси честно называют гранулярность. Плашка в шапке называет реальную причину: «Биржевые данные недоступны в вашем регионе» после `451`, «Биржа не отвечает, используем резервный источник» после таймаутов. Это разные строки локализации.

- Ни один экран не остаётся с вечным лоадером. У каждого источника таймаут и состояние ошибки с кнопкой повтора.

Проверить перед сдачей: VPN с американским IP, пройти все экраны, скриншоты в README. Это часть критериев готовности.

### Сторы, privacy и юридический текст

- App Store 3.1.5 (крипта). Ручной трекер, который не хранит и не переводит криптовалюту, по заявленному функционалу не является кошельком или биржей. Это снижает риск, но не гарантирует решение ревью. Дополнительно держим в уме 3.2.1(viii) и 5.1.1(ix): приложение не позиционируется как управление инвестициями или персональные рекомендации.

- Заметка для ревью: «TradeLens displays public market data from Binance and CoinGecko and keeps a manual portfolio on the device. No trading, no accounts, no wallets. If exchange data is unavailable in your region, the app falls back to CoinGecko automatically; the source can also be switched in Settings.»

- Privacy policy обязательна и должна быть доступна по ссылке из стора и из приложения. Отдельная страница на GitHub Pages. В ней перечислены все SDK и что они собирают: Firebase (Remote Config, идентификатор установки), OneSignal (push-токен, теги), AppsFlyer (идентификатор установки, параметры OneLink), Sentry (краши, модель устройства), Anthropic (рыночные данные текущей пары и ключ пользователя, только по действию пользователя).

- App Privacy в App Store Connect и PrivacyInfo.xcprivacy это разные вещи. Первое заполняется по фактическому сбору всех SDK, второе собирается из манифестов SDK плюс свои required reason API. Оба в чеклисте дня 8.

- ATT. Определяется реальным трекингом, а не названием фичи. AppsFlyer в режиме без IDFA и без сопоставления с чужими данными не требует ATT-промпта. В настройках SDK отключаем сбор IDFA и фиксируем это в ADR. Если ревью спросит, ответ готов.

```

packages/
core/ # Decimal, Result, логгер, env, ошибки
domain/ # сущности + интерфейсы репозиториев, без зависимостей

data_local/ # Drift: портфель, кэш свечей, настройки
```

### Источники данных

Один интерфейс, три реализации. Feature-слой не знает, откуда пришла цена.

```
/// Актив описывается независимо от источника: CoinGecko `bitcoin/usd`
/// и Binance `BTCUSDT` это разные инструменты одного актива.
@freezed class Asset { ... } // id 'btc', base 'BTC'
@freezed class Instrument { ... } // value equality: ключ family-провайдера
@freezed class Quote { ... } // instrument, Decimal price, DateTime at

abstract interface class MarketDataSource {
String get id; // 'binance', 'binance_us', 'coingecko'
String get attribution; // текст для DataSourceBadge
Capabilities get capabilities; // orderBook, trades, klineStream,
// intervals: {1m,15m,1h,1d} | {auto}, volume
Instrument? instrumentFor(Asset a, String quote);
Future> quotes(List ins);
Future> klines(Instrument i, Interval iv, {int limit = 500});
Stream quoteStream(List ins);
Stream klineStream(Instrument i, Interval iv);
Stream orderBookStream(Instrument i); // top-10 целиком
Stream tradeStream(Instrument i);
}
```

| Источник | REST | WS | Что используем |

| Binance Global | api.binance.com/api/v3 | stream.binance.com:9443/stream | `ticker/24hr`, `klines`; стримы `@miniTicker`, `@kline_1m`, `@depth10@100ms` (готовый снапшот top-10), `@trade`. Комбинированный стрим с конвертом `{stream, data}`, имена стримов в нижнем регистре. Хосты только для рыночных данных: `data-api.binance.vision`, `data-stream.binance.vision` |

| Binance US | api.binance.us/api/v3 | stream.binance.us:9443/stream | Те же эндпоинты, меньше пар. Список пар для US отдельный в конфиге |

| CoinGecko | api.coingecko.com/api/v3 | нет | `simple/price` батчем по 20 id с `include_24hr_change`, `coins/{id}/ohlc` с автоматической гранулярностью и без объёма; timestamp там это время закрытия свечи, адаптер приводит его к `openTime` вычитанием гранулярности, чтобы кэш и чарт работали в одной системе. Опрос раз в 60 с только в foreground. Capabilities: без стакана, ленты, объёма и выбора интервала |

Region resolver живёт в `data_market`: проверяет источники по цепочке из раздела «Гео-блокировки», результат кладёт в настройки с TTL 24 ч и отдаёт как `Provider<MarketDataSource>`. Смена источника переподписывает все стримы через `ws_client`.

Портфель и смена источника. Позиция хранит актив, валюту котировки и цену входа. Оценка считается только по котировке в той же валюте. Если активный источник не даёт сопоставимой цены (например, у Binance US нет пары), оценка показывается как недоступная, а не пересчитывается молча в другой валюте. Кэш свечей и котировок ключуется по `sourceId + instrument + interval`, история разных источников не склеивается.

Лимиты. Binance: около 300 WS-подключений за 5 минут с одного IP, до 5 исходящих сообщений в секунду на соединение (ping, pong, команды подписки), весовые лимиты REST на минуту по заголовку `X-MBX-USED-WEIGHT-1M`. REST-запросы истории идут через очередь с учётом веса и заголовка использованного веса. На `429` читать `Retry-After` и ждать, на `418` остановить запросы до истечения бана.

### WebSocket-слой

Уменьшенная копия того, что живёт в Bitsgap, с теми же уроками. Это главная тема для разговора на интервью, поэтому код пишется чисто и с тестами.

- Одно соединение на источник, комбинированный стрим. Подписки добавляются и снимаются JSON-командами `SUBSCRIBE` / `UNSUBSCRIBE` с id. Все исходящие сообщения идут через одну очередь с ограничителем 4 сообщения в секунду, запас в одно сообщение оставлен транспортным pong. Изменения реестра за 250 мс собираются в один SUBSCRIBE и один UNSUBSCRIBE.

- Реестр подписчиков: ключ стрима → счётчик слушателей. Подписка на бирже открывается на первом слушателе, закрывается на последнем с задержкой 2 с, чтобы переход между экранами не дёргал сокет.

- Half-open detection: Binance шлёт WebSocket ping-фрейм каждые 20 с, `dart:io` отвечает pong на транспортном уровне сам, в поток данных эти фреймы не попадают. Поэтому детект строится на своём таймере: если 60 с не было ни одного data-кадра по активным подпискам, соединение считается мёртвым и пересоздаётся. Для тихих пар держим подписку на один miniTicker ликвидной пары как heartbeat. Это тот же класс бага, который ловили в Bitsgap.

- Реконнект с экспоненциальной задержкой 1, 2, 4, 8, максимум 30 с, с джиттером. Binance закрывает соединение каждые 24 ч, это штатный реконнект. После реконнекта восстанавливаются все подписки из реестра, свечи добирают пропуск по REST от последней известной `openTime`, стакан приходит следующим снапшотом стрима.

- Стакан: `@depth10@100ms` отдаёт полный top-10 каждые 100 мс, локальное состояние заменяется целиком. Вариант с диффами `@depth@100ms`, буферизацией до REST-снапшота и стыковкой по `U/u` записан в ADR как осознанно не выбранный: он нужен только для полного стакана.

- Батчинг: тики копятся и отдаются в UI одним кадром раз в 16 мс. Парсинг JSON в изоляте не нужен на таких объёмах, и это тоже ответ на интервью: замерить, прежде чем оптимизировать.

- Жизненный цикл: в фоне соединение закрывается через 30 с, при возврате открывается заново. Состояние соединения видно в UI точкой в шапке. Provider стрима при dispose реально снимает слушателя с реестра, тест на это обязателен.

### Чарт на CustomPainter

- Пакет `chart` без зависимостей от feature-слоя, чтобы позже уйти на pub.dev. Публичный API: `CandleChart(candles, interval, overlays, onCrosshair)`.

- Два painter-а: свечи с объёмом и слой кроссхейра. Разделение, чтобы движение пальца не перерисовывало свечи. `shouldRepaint` по идентичности списка и viewport. Новая свеча с тем же `openTime` обновляет последнюю, а не добавляет.

- Viewport хранит индекс первой видимой свечи и ширину свечи в пикселях. Зум меняет ширину, пан меняет индекс. При приходе новой свечи viewport «прилипает» к правому краю, если пользователь не отматывал историю.

- Шкала цены считается по видимому диапазону, метки через `TextPainter` с кэшем по значению. Шкала времени по интервалу.

- Decimal только в данных, в painter уже double. Граница конверсии одна, в мапере viewport.

- Golden-тесты на три состояния: пусто, 50 свечей, 500 свечей с кроссхейром. Бенчмарк перерисовки в `test/benchmark` как аргумент про 60 FPS. Режим без объёма и с произвольной гранулярностью нужен для CoinGecko-fallback, это часть API виджета.

### Хранилище и портфель

- Drift с четырьмя таблицами: `positions` (assetId, quote, qty, avgPrice как TEXT для Decimal, createdAt), `candle_cache` (sourceId, instrument, interval, openTime, ohlcv), `last_quotes` (sourceId, instrument, price, at), `settings` (key, value).

- Кэш свечей: последние 500 на источник, инструмент и интервал, пишется батчем после REST-загрузки, читается первым при открытии экрана. Сеть подменяет кэш, а не ждёт его. Холодный старт без кэша и без сети показывает пустое состояние с пояснением, это тоже спроектированный экран.

- Офлайн-оценка портфеля считается по `last_quotes` с подписью «на 12:40», а не по свечам. Без сохранённой котировки оценка недоступна.

- Портфель: `PortfolioValuation` в domain как чистая функция от позиций и тикеров. Тестируется без Drift и без сети.

- Миграции: схема стартует с v1, а в день 5 добавляется реальная v2 (поле `note` у позиции) с тестом миграции через `drift_dev` schema tooling, который проверяет сохранность данных. Создание схемы это ещё не миграция.

### Riverpod: правила

- Riverpod 3.x, только codegen: `@riverpod` для провайдеров, `@Riverpod(keepAlive: true)` для источников и сокета. Стримы объявляются функцией, возвращающей `Stream<T>`.

- Стримы биржи это family-провайдеры с параметром instrument. AutoDispose срабатывает, когда исчезает последний слушатель, а не при уходе с экрана: котировка, которую смотрит и экран пары, и портфель, остаётся живой, пока её смотрит портфель. Тест проверяет именно это: счётчик реестра уменьшается только после ухода последнего потребителя.

- UI читает только `AsyncValue` и рендерит три состояния явно. Никаких `.value!`.

- Бизнес-логика в `Notifier`-ах, не в виджетах. Портфельный Notifier тестируется через `ProviderContainer` с override источника.

- Одна страница в docs/decisions про то, чем это отличается от Provider, Bloc и MobX, и что изменилось в 3.x. Это будет спрошено.

### Remote Config и SDUI

Firebase Remote Config хранит флаг `ai_insights_enabled` и JSON `insights_screen`. Пакет `sdui` парсит JSON в дерево узлов и рендерит.

```
{
"schema": 1,
"children": [
{"type": "header", "text": {"en": "Market today", "ru": "Рынок сегодня"}},
{"type": "ticker_card", "symbol": "BTCUSDT", "showSparkline": true},
{"type": "text", "text": {"en": "...", "ru": "..."}, "style": "muted"},
{"type": "button", "label": {"en": "Open BTC"}, "action": {"route": "/p/BTCUSDT"}},
{"type": "list", "children": [ ... ]}
]
}
```

- Пять типов узлов: header, text, ticker_card, button, list. Неизвестный тип рендерится как серая заглушка с именем типа в debug и пустым местом в release. Невалидный JSON или отсутствие обязательного поля: остаётся последний валидный экран, ошибка в Sentry.

- `schema` сверяется с поддерживаемой версией. Старая схема рендерится, новая показывает дефолтный экран из ассета.

- Дефолтный JSON лежит в ассетах и подставляется, пока Remote Config не подтянулся или недоступен. Экран никогда не пустой.

- Fetch и activate: при старте `fetchAndActivate` с таймаутом, дальше подписка на `onConfigUpdated` с `activate()`, чтобы правка в консоли применялась вживую на демо. Дефолтный minimum fetch interval 12 ч в debug снижен до нуля.

- Текст узла берётся по локали приложения с fallback на en. Действия ограничены белым списком маршрутов go_router, произвольные URL из JSON не открываются.

- Действия узлов проходят через go_router, поэтому SDUI-кнопка и deep link используют один и тот же маршрут.

- Тест: JSON-фикстуры → дерево → golden экрана. Отдельный тест на неизвестный тип.

### Deep links, атрибуция, пуши

- Прямые ссылки: Universal Links (apple-app-site-association на домене) и Android App Links (assetlinks.json). Маршрут `/p/{symbol}`. Они работают только на установленном приложении и сами по себе ничего не переносят через установку.

- Deferred deep link: AppsFlyer, план Zero (бесплатный), OneLink и Unified Deep Linking. Для нового пользователя SDK отдаёт `deep_link_value` и `deep_link_sub1…sub10`, поэтому в ссылке пара идёт в `deep_link_value`, источник в `deep_link_sub1`. Произвольные параметры вроде `src` через установку не переживут. Firebase Dynamic Links закрыт 25.08.2025 и не рассматривается. Запасной вариант Branch: у новых аккаунтов пробный период 30 дней, потом платный план, поэтому только если AppsFlyer не заработает.

- Проверка на реальном iPhone в день 7: удалить приложение, открыть OneLink в Safari, установить из TestFlight, первый запуск открыл нужную пару. Симулятор для этого сценария не годится.

- Атрибуция: параметры установки сохраняются в settings и показываются на экране «О приложении» под заголовком «Источник установки». Сбор IDFA в SDK отключён, данные не сопоставляются с чужими и не передаются брокерам, поэтому это не tracking по определению Apple и ATT-промпт не требуется. Если при чтении условий AppsFlyer окажется иначе, ATT добавляется.

- OneSignal: инициализация, запрос разрешения по явному действию пользователя, тег `fav_symbol`. Тап по пушу с `route` в data идёт в go_router. Проверка тега на сервере это ручной smoke через дашборд, автотест проверяет только вызов адаптера.

- iOS: Push capability, Associated Domains. Android: intent-filter с autoVerify.

### AI-сводка движения через Claude API

Что это. Кнопка называется «Сводка движения», не «Объяснить». По свечам и стакану можно описать, что произошло с ценой и объёмом, но нельзя установить причину. Системный промпт запрещает выдумывать новости и события, ответ содержит источник и время данных.

Ключ. Пользователь вводит свой API-ключ в настройках, ключ лежит в flutter_secure_storage и отправляется только на api.anthropic.com. Без ключа кнопка ведёт на экран настроек с пояснением. Никакого прокси: проект принципиально без бэкенда, и это записано как ограничение, а не как план.

Модель. Актуальная на момент реализации из семейства Claude, идентификатор в конфиге, не в коде. Перед реализацией свериться со скиллом claude-api: имена моделей, цены, параметры structured output.

#### Поток

- Экран согласия перед первым вызовом: какие данные уходят и куда.

- Системный промпт: аналитик рынка, только описание фактов из переданных данных, без причин и рекомендаций, 5–7 предложений, язык пользователя.

- Два tool: `get_klines(instrument, interval, limit)` и `get_orderbook(instrument)`. Аргументы валидируются по белому списку инструментов и интервалов. Данные берутся из уже загруженных провайдеров без нового похода в сеть. В режиме fallback стакан возвращает `unavailable`.

- Tool loop ограничен 3 итерациями и бюджетом токенов, есть отмена по уходу с экрана.

- Стриминг текста в UI по SSE.

- Второй вызов со structured output: `{trend, volatility, keyLevels[], dataSource, dataAsOf}` для блока под текстом.

- Ошибки: 401 → «проверь ключ», 429 → «подожди», сеть → «повтори». Стоимость считается из `usage` по тарифу модели из конфига и суммируется по всем вызовам сессии.

- Дисклеймер под каждой сводкой.

- Тесты: клиент с фейковым HTTP, разбор SSE-чанков, tool loop на 2 итерации и обрыв на лимите, парсинг structured output с невалидным JSON.

- Флаг `ai_insights_enabled` из Remote Config выключает фичу без релиза.

### Безопасность

- SSL pinning по публичному ключу (SPKI) для api.binance.com и api.anthropic.com через `IOHttpClientAdapter.validateCertificate` в Dio: обычная проверка цепочки и hostname остаётся, поверх неё сравнивается SPKI-хеш. `badCertificateCallback` не подходит, он вызывается только для сертификатов, не прошедших системную валидацию. Тест: доверенный сертификат с чужим пином отклоняется. Честное ограничение: ключи Binance и Anthropic мы не контролируем, поэтому «запасной пин» это текущий и предыдущий, а при ротации на их стороне приложение ломается до обновления. Это записано в ADR как известный компромисс pinning без своего бэкенда.

- Secure storage для API-ключа Claude. Ключ не логируется, не попадает в Sentry-контекст.

- Никаких секретов в репозитории: Firebase-конфиги, OneSignal и AppsFlyer id, CoinGecko demo-ключ через `--dart-define-from-file` и GitHub Secrets. Пример файла `env.example.json` в репозитории. Это прячет ключи от git, но не от извлечения из бинарника, что честно записано. Урок из аудита безопасности Bitsgap: прод-keystore в git не повторять.

- Sentry с фильтром breadcrumbs по URL, чтобы ключ не утёк в хлебных крошках.

### Риски и принятые решения

| Риск | Вероятность | Решение |

| Условия бирж изменились | средняя | Перечитать перед первой публичной сборкой, дату в README. Интерфейс источника позволяет заменить Binance на Bybit за день |

| Ревью Apple из региона с закрытым Binance видит пустой экран | высокая без fallback | Region resolver и CoinGecko-режим в must, ручной выбор источника в настройках. Прогон под VPN в критериях готовности |

| Название занято в сторах | средняя | Проверить в день 1, запасные имена в PRD |

| Ключ Claude в приложении | закрыт | Ключ пользователя в secure storage. Прокси не планируется, проект без бэкенда |

| Квота CoinGecko на общий ключ исчерпана | средняя | Батч по 20 монет, опрос раз в 60 с только в foreground, понятное сообщение при исчерпании. Для showcase достаточно |

| AppsFlyer Zero не даёт нужных полей UDL или меняет условия | средняя | Абстракция `AttributionProvider`, проверка полей в день 1. Запасной Branch с учётом платного плана после пробного периода |

| Условия источника запрещают передачу данных в Claude API | проверить | Читать условия в день 1. Если запрет есть, AI-фича переводится на данные того источника, который передачу разрешает, или отключается флагом. Агрегаты вместо сырых свечей разрешения сами по себе не создают |

| Скоуп разрастается | высокая | Список не-скоупа и порядок выбрасывания функций записаны. Каждая новая идея идёт в docs/decisions/backlog.md, а не в код |

| Fastlane match, keychain в CI и Beta App Review съедают день | средняя | Первый ручной upload и внешняя группа в день 1, дальше только повторные загрузки |
